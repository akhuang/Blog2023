这是基础篇的收尾。前面的文章让 Agent 跑起来，这一篇解决最后一个问题：怎样把脑中的要求交代完整。

很多人第一次用 Agent，失败并不是因为不会写“高级提示词”，而是没有把工作交代完整。Agent 能读文件、运行命令、不断检查结果，但它不知道你脑中没说出来的背景。任务说明的作用，是把这些背景变成一张可以执行、也可以验收的工作单。

一张合格的工作单有六项：**目标、资料、范围、约束、交付物、验收标准**。它不一定很长，但每一项都要能指向看得见的东西。

## 先看一句很差的指令

```text
帮我整理一下这些资料，写个好一点的周报。
```

问题不在于语气随便，而在于几乎每个词都需要猜：“这些资料”在哪个文件夹？“整理”是改文件名、提取信息，还是总结？周报写给谁？“好一点”是更短、更完整，还是更正式？最终放在哪里？哪些数字必须复核？

如果 Agent 直接开工，它可能写得很流畅，却不是你需要的东西。下面把这句话一步步改成可执行的任务。

## 第一步：先写目标

```text
根据本周项目记录，生成一份给部门经理看的项目周报初稿。
```

现在有了方向和对象，但 Agent 还不知道去哪里找事实。

## 第二步：指出资料和范围

先准备清楚的目录：

```text
C:\AgentPractice\weekly-report\
├─ input\
│  ├─ 本周记录.md
│  ├─ 项目清单.csv
│  └─ 周报模板.md
└─ output\
```

再补一句：

```text
只读取 input 中的三个文件。不要读取其他目录，也不要修改 input 中的原文件。
```

“资料”告诉 Agent 事实从哪里来；“范围”告诉它这次做到哪里为止。范围不是客套话，它决定 Agent 会不会把历史文件、无关项目或旧输出也混进来。

## 第三步：写清约束

```text
不得补写资料中没有的进度、日期、金额和责任人。
无法确认的内容写“待确认”，并注明来源文件。
全文控制在 1200 字以内，使用简洁的内部汇报语气。
```

约束不是越多越好。只写会改变结果的规则：哪些事实不能猜、哪些文件不能动、篇幅和口吻是什么。至于 Agent 内部要调用哪个命令，不必替它设计。

## 第四步：指定交付物

```text
将结果保存为 output/项目周报初稿.md。
结构固定为：本周完成、进行中、风险与待确认、下周计划。
另在文末附“资料覆盖清单”。
```

只要一个聊天回答时，结果容易淹没在对话里。指定文件名、格式和结构后，交付物就能打开、修改、转交，也能与下一版比较。

## 第五步：给出验收标准

```text
完成前自查：
1. input 中每个项目都已出现，或在资料覆盖清单中说明为何未采用；
2. 所有日期、数字和负责人都能追溯到来源文件；
3. “已完成”和“计划完成”没有混写；
4. output 中只新增约定的交付文件。
```

“写好一点”没有办法判断完成；四条验收标准可以。它们让 Agent 知道什么时候停，也让你知道该检查什么。

## 一份可以直接复制的完整模板

以后换成资料目录、信息抽取、版本差异或报告初稿，只需替换方括号中的内容：

```text
【目标】
根据 [资料]，为 [使用对象] 完成 [任务结果]。

【资料】
工作目录：[完整路径]
输入文件：[文件或文件夹清单]

【范围】
只处理 [范围]。
不读取 [范围外内容]，不修改 [原始文件]。

【约束】
- 不编造输入中没有的事实；缺失内容标为“待确认”。
- [篇幅、口吻、字段、命名规则等真正影响结果的要求]
- 若关键资料缺失，先说明缺什么，不要自行假设。

【交付物】
保存到：[输出路径和文件名]
格式与结构：[Markdown/CSV，以及固定章节或字段]

【验收标准】
1. [覆盖了哪些输入]
2. [关键事实如何追溯]
3. [哪些错误必须为零]
4. [输出目录中应出现什么]

开始时先列出你识别到的输入文件和准备执行的步骤；确认路径无误后再生成交付物。完成后按验收标准逐项报告结果。
```

这套模板的重点不是六个标题，而是一条关系：你把隐含要求变成可观察的输入和结果，Agent 才能在工作过程中自行判断下一步；你再用验收标准接住结果，而不是凭“看起来不错”放行。

## 什么时候聊天，什么时候用 Agent

**用聊天更合适：** 解释一个概念、讨论思路、润色一小段已经贴出的文字、比较几个方案，或者你只需要一次回答，不需要它读取本地文件和留下交付物。

**用 Agent 更合适：** 任务涉及多个本地文件，需要批量改名、提取、转换或比较；需要运行命令观察结果；过程会分成几步；最后还要保存一个可继续使用的文件。

一个更准确的判断是：**只围绕你贴出的内容得到一次回答，聊天通常更轻；需要访问本地材料、调用工具，或围绕结果反复执行和检查，就用 Agent。** Agent 也可以只读分析本地文件，并不一定要修改它们。如果任务里有正式发送、审批、付款或对外承诺，Agent 可以准备草稿和依据，最后动作仍交给有权限的人。

第一次不必追求完美模板。先把六项写全，跑一次，看输出哪里偏了，再把那条差异改成下一次的约束或验收标准。你训练的不是一句神奇提示词，而是一种把工作说清楚的能力。
