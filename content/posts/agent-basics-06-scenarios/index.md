先改掉一个容易误导人的想象：Agent 最适合小白的起点，不是“接管整台电脑”，而是接收一个清楚的文件夹，把其中的资料变成一份可以检查的新文件。

你可以先在 Windows 中准备一个练习目录：

```text
C:\AgentPractice\demo\
├─ input\    原始资料
└─ output\   Agent 的交付物
```

把练习副本放进 `input`，在 `demo` 文件夹中启动 Claude Code，并明确要求结果只写入 `output`。这样，输入、动作和结果都看得见。Claude Code 擅长读写文件、运行命令和调用已经安装好的工具；它并不等于一个能随意点击 Word、Excel、Outlook 所有按钮的桌面机器人。Office 文件若无法直接读取，可以先另存为 PDF、CSV 或纯文本。

下面五个场景，足够覆盖多数人的第一次实践。

## 场景一：给一堆资料做目录

**输入：** `input` 中有会议纪要、制度说明和项目材料，格式以 Markdown、TXT、可复制文字的 PDF 为主。

**动作：** 让 Agent 先列出文件，再按“文件名、主题、日期、三句话摘要、待确认项”整理，不改原文件。

**结果：** `output/资料目录.md`。以后找资料时，先看这一页，不必逐个打开文件。

**人工验收：** 对照文件夹核对数量，随机打开三份原文，检查标题、日期和摘要是否真的来自原文。

**不适用边界：** 扫描件、手写照片、加密 PDF 可能读不到；没有 OCR 结果时，不应让 Agent 猜字。

## 场景二：批量整理文件名

**输入：** 一批类似 `新建文档(3).pdf`、`最终版2.docx` 的文件，以及你希望采用的命名规则。

**动作：** 先让 Agent 生成“旧文件名 → 新文件名”的映射表。你确认后，再让它对练习副本执行重命名。

**结果：** 命名统一的文件，以及 `output/重命名清单.csv`，每一次变化都有记录。

**人工验收：** 检查文件总数没有变化，重点查看重名、日期不明、无法判断项目归属的条目。

**不适用边界：** 文件名本身不含足够信息时，Agent 不能凭空判断合同号或责任人；需要先补充映射表。

## 场景三：从资料中抽取字段

**输入：** 多份格式相近的通知、报价说明或会议记录，以及明确的字段表，例如“项目、负责人、承诺日期、风险、原文出处”。

**动作：** 让 Agent 逐份读取，只提取原文出现的内容；缺失字段写“未找到”，同时保留来源文件名和原句。

**结果：** `output/信息汇总.csv`，可以再用 Excel 打开、筛选和补充。

**人工验收：** 按高风险字段回到原文复核，尤其是金额、日期、否定词和责任人。

**不适用边界：** 这适合整理事实，不适合替人做合同定性、财务确认或最终审批。

## 场景四：把零散记录变成报告初稿

**输入：** 本周工作记录、项目清单、已有报告模板，以及报告的对象和篇幅要求。

**动作：** 让 Agent 按模板归类事实，区分“已完成、进行中、风险、下周计划”，缺少证据的判断标成待确认。

**结果：** `output/周报初稿.md`。它是一份可编辑的草稿，不是已经发出的邮件。

**人工验收：** 检查有没有遗漏关键项目、把计划写成完成、把推测写成事实，再由负责人调整口吻。

**不适用边界：** 没有原始记录时，Agent 只能写出流畅的空话；对外承诺和正式发送仍由人决定。

## 场景五：检查两个版本的差异

**输入：** 同一份说明的旧版和新版，最好是 TXT、Markdown、CSV，或从 Office 导出的可比较文本。

**动作：** 让 Agent 逐段比较，按“新增、删除、修改、可能影响”列出差异，并引用两个版本的原句。

**结果：** `output/版本差异.md`，供评审者快速定位变化。

**人工验收：** 打开原文件核对关键变化，确认表格、脚注、批注和排版信息是否在导出时丢失。

**不适用边界：** 它不能替代 Word 的正式修订记录，也不能仅凭文字差异判断一项业务变更是否已经生效。

这五个场景背后其实只有一条工作方式：把原始资料放在一边，让 Agent 产出一个新的、可追溯的文件，再由人验收。任务越能落到具体文件，Agent 越容易做实；只说“帮我弄好一点”，它就只能猜。
