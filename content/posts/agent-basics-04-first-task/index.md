环境装好以后，先别拿公司的真实项目练手。第一个 Agent 任务应该足够小：材料看得完，结果能肉眼核对，即使做错也不会影响任何人。

这一篇用三份本地文件走完一条最小工作路径：**读取材料 → 说出计划 → 创建结果 → 对照检查**。任务不是写代码，而是把会议信息整理成一份 Markdown 行动清单。做完以后，你会第一次看清“聊天回答”和“Agent 操作文件”的差别。

## 第一步：下载并打开练习文件夹

先下载我准备好的 [Agent 第一个任务练习包](agent-first-task.zip)。在文件资源管理器中找到下载的 ZIP，右键选择 **全部解压**，把 `agent-first-task` 文件夹放到“文档”目录。不要拿现有工作文件夹代替这个练习目录。

进入解压后的文件夹，你应该看到 `requirements.txt`、`meeting-notes.txt` 和 `template.txt`。三份材料都很短，可以双击打开，先看一眼里面写了什么；稍后你就能逐项判断 Agent 有没有漏掉、写错或自己编造信息。

回到这个文件夹，在空白处右键选择 **在终端中打开**。如果菜单里没有这一项，点击资源管理器顶部的地址栏，输入 `wt` 后按回车。打开的 Windows Terminal 会自动位于当前练习文件夹，不需要手工输入一串切换目录的命令。

## 第二步：让 Agent 先读，再给计划

仍在当前目录运行：

```console
claude
```

把下面这段话完整发给 Claude Code：

```text
请读取当前文件夹中的 requirements.txt、meeting-notes.txt 和 template.txt。
先不要创建或修改任何文件。
请告诉我：你理解的目标是什么、准备读取哪些事实、最终会创建什么文件，以及你会怎样检查结果。
```

这一步很重要，不是为了让计划看起来正式，而是让你在写文件之前确认 Agent 是否理解了任务。一个合格的计划应当提到：从会议记录提取三项任务，沿用模板结构，把未确定的开始时间放进“待确认”，最后重新读取输出做核对。

如果它理解错了，直接指出哪一点不对，让它重述计划。此时还没有文件变化，纠正成本最低。

## 第三步：授权它创建一个结果文件

计划正确后，再发送：

```text
按刚才的计划执行。请保留三个原始文件不变，创建 行动清单.md。
完成后告诉我你创建了什么，但先不要继续改动其他内容。
```

Claude Code 可能会展示即将写入的内容，或询问是否允许创建文件。确认目标确实是当前练习目录下的 `行动清单.md` 后同意即可。

完成时，结果至少应包含三行任务：王宁整理截图、李晓收集问题、陈晨确认会议室和设备；负责人和截止时间应与原文一致。“具体开始时间”只能出现在待确认项中，不能被补成一个看似合理的时间。

## 第四步：让 Agent 检查，再亲手看一遍

先让 Agent 做一次只读核对：

```text
请重新读取三个原始文件和 行动清单.md，逐项检查负责人、截止时间和待确认信息。
只报告检查结果，不要修改文件。
```

它应该明确告诉你哪些内容一致，是否有遗漏。然后输入 `/exit` 退出 Claude Code，回到文件资源管理器。你会看到新出现的 `行动清单.md`；双击打开，亲手查看结果。

最后只核对四件事：三个原始文件还在；新增文件名正确；三个人与三个期限没有串位；未知的开始时间仍然是“待确认”。这比一句“任务完成”更有价值，因为你检查的是电脑上真正留下来的结果。

## 这次任务里，Agent 实际做了什么

如果你只是把一段文字粘贴到普通聊天窗口，模型可以生成一张表，但它没有接触这个练习目录。刚才的 Claude Code 则先读取当前目录，向你说明计划，调用文件工具创建 `行动清单.md`，再重新读取文件完成核对。模型负责理解和组织，Agent 把理解变成了一连串真实动作。两者都能“回答”，区别在于后者在你的电脑上留下了可以再次打开和继续使用的结果。

以后把练习材料换成日志、需求说明或项目文档，这条路径仍然成立：先把任务范围放进一个明确目录，让 Agent 读取事实，确认计划，再生成一个可以直接检查的结果。第一次不需要复杂流程，先把这条最短路径走通。
